# AI Talking 产品 PRD

创建日期：2026-06-13

## 背景

项目需求是一款可以与 AI 对话的应用：用户打开摄像头与麦克风后，AI 能看到摄像头中的视频内容，听到用户说的话，并给出恰当回应。验收重点不只在“能对话”，还包括视觉内容理解准确性、语音交互自然度、流畅性，以及端云协同下的成本控制策略。

本 PRD 面向当前 Web 版 AI Talking。产品以浏览器为主要入口，用户无需安装客户端即可体验摄像头、语音和多模态对话；移动端可以通过 Capacitor 壳或后端托管前端静态资源进行演示。

## 产品目标

| 目标 | 说明 | 当前状态 |
|---|---|---|
| 多模态对话可用 | 用户可以基于摄像头画面和语音/文本向 AI 提问 | 已实现 |
| 视觉理解可信 | AI 获取的画面应尽量接近用户提问时看到的画面 | 部分实现，准备补强发送即取帧 |
| 语音交互自然 | 用户能用语音输入，AI 能流式回复并播报 | 已实现基础能力，准备优化播报分句 |
| 成本可控可解释 | 图像、语音、上下文和 TTS 成本有控制策略 | 已实现多项策略，准备增加模式化入口 |
| 交付文档完整 | 提供用户故事和成本控制说明 | 本次补充 |

## 目标用户与场景

| 用户 | 场景 | 关键诉求 |
|---|---|---|
| 普通用户 | 对着摄像头展示物体并提问 | AI 能结合画面和语言回答 |
| 学习用户 | 拿题目、书页、绘本给 AI 看 | AI 能识别文字和细节，并用自然语言解释 |
| 长时间陪聊用户 | 做家务、烹饪、整理时语音提问 | 语音输入和播报自然，成本不过高 |
| 演示/验收人员 | 现场验证视觉、语音、成本策略 | 状态可见、行为可解释、失败可定位 |

## 核心交互

### 摄像头与画面传输

用户进入页面后，摄像头模块显示实时视频画面。用户可以点击“启用摄像头”打开权限，再点击“开始传输画面”启用对话帧更新。未开启传输时，右下角缩略图仍会本地更新，便于测试抽帧和压缩；开启传输后，系统只在检测到画面变化时更新对话使用的帧。

画面设置以浮层形式展开，不改变摄像头画面尺寸。用户可设置抽帧频率、图像质量上限/下限、图片分辨率和场景预设。智能自适应质量开启时，复杂画面使用更高 quality，简单画面使用更低 quality。

### 语音与文本对话

用户可以直接输入文字，也可以点击“语音输入”说话。语音识别结果会回填到输入框；识别到句子结束后自动发送。AI 回复以流式文本逐步显示，并按句播报。若用户开始输入或再次语音输入，当前 AI 播报会停止。

### 对话摘要与成本反馈

用户可以在对话模块顶部展开“对话摘要”面板，开启或关闭摘要，并调节摘要触发 token 阈值。右上角状态栏展示会话 token 统计、调用次数、总 token、节省 token 和估算费用，让成本策略在演示时可见。

## 视觉准确性要求

| 要求 | 当前方案 | 待补强 |
|---|---|---|
| AI 能看到用户展示内容 | 发送请求时携带当前帧 | 发送时立即抓取最新帧 |
| 能捕捉局部细节变化 | 64x64 多指标变化检测 | 可按模式进一步调低阈值 |
| 能识别文字/细节 | 高清预设提高分辨率和质量 | 增加文本识别/讲题预设 |
| 不上传无意义画面 | 变化检测控制发送帧更新 | 区分预览帧和发送帧状态 |

## 埋点方案设计

埋点方案是产品设计内容，当前不一定实现。设计目标是帮助评估视觉准确性、语音交互质量、成本控制效果和异常分布，不采集原始音频、原始图片或完整对话内容。

### 事件定义

| 事件名 | 触发时机 | 关键属性 | 决策用途 |
|---|---|---|---|
| `camera_permission_result` | 摄像头权限成功或失败 | result、error_code、platform | 判断权限失败是否影响转化 |
| `microphone_permission_result` | 麦克风权限成功或失败 | result、error_code、platform | 判断语音入口可用性 |
| `frame_captured` | 本地抽帧完成 | image_size、effective_quality、complexity_level、estimated_bytes、is_transmitting | 评估抽帧频率和压缩策略 |
| `frame_sent_to_model` | 对话请求携带图片 | image_size、estimated_bytes、changed_score、scene_preset | 评估视觉 token 成本 |
| `asr_sentence_detected` | 语音识别句子结束 | duration_ms、text_length、is_stop_command | 评估语音输入自然度 |
| `message_sent` | 用户发送文本或语音消息 | input_type、has_image、text_length、scene_preset | 分析核心对话使用路径 |
| `ai_stream_started` | 收到首个 AI 文本片段 | latency_ms、has_image | 评估首字延迟 |
| `ai_stream_done` | AI 回复完成 | duration_ms、reply_length、prompt_tokens、completion_tokens | 评估回复质量和成本 |
| `tts_playback_started` | 开始播报 | text_length、tts_engine | 评估播报使用率 |
| `tts_interrupted` | 用户打断播报 | reason、played_duration_ms | 判断播报是否过长或打断频繁 |
| `summary_applied` | 对话摘要触发 | replaced_messages、saved_tokens、summary_tokens | 验证摘要降本效果 |
| `cost_mode_changed` | 用户切换成本/质量模式 | from_mode、to_mode | 评估成本模式是否被理解和使用 |
| `api_error` | 接口失败 | api_name、error_code、duration_ms | 定位模型、网络或后端问题 |

### 数据边界

埋点默认不上传原始图片、原始音频、完整用户文本和完整 AI 回复。可上传长度、耗时、token 数、图片估算体积、复杂度等级、是否携带图片等结构化元信息。若后续需要质量分析样本，应单独增加用户授权和脱敏机制。

### 指标看板

| 看板 | 核心指标 |
|---|---|
| 多模态使用 | 对话次数、携图消息比例、场景预设使用分布 |
| 视觉质量 | 抽帧次数、发送帧次数、复杂度分布、平均图片体积 |
| 语音体验 | 语音输入占比、识别句子时长、播报打断率 |
| 成本 | 单次对话 token、每轮图片体积、摘要节省 token |
| 稳定性 | API 错误率、权限失败率、流式中断率 |

## 验收标准

| 场景 | 验收方式 |
|---|---|
| 摄像头可用 | 打开页面后启用摄像头，实时预览正常显示 |
| 麦克风可用 | 点击语音输入，说话后识别文本进入对话 |
| AI 看图回答 | 展示物体或页面，提问后 AI 回复与画面相关 |
| 流式回复 | AI 回复逐步显示，不等待完整生成 |
| 语音播报 | AI 回复过程中能听到播报，用户输入可打断 |
| 成本可见 | 右上角状态栏展示 token 和估算费用 |
| 成本可控 | 调整图片质量、分辨率、摘要阈值后，状态随之变化 |
| 文档完整 | 技术方案、PRD、用户故事与成本控制说明文档均可提交 |
