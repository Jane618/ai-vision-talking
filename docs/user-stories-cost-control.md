# 用户故事与成本控制说明

创建日期：2026-06-13

## 文档目的

本说明用于解释 AI Talking 多模态对话应用的用户故事实现情况，以及端云协同成本控制策略。应用目标是让用户打开摄像头与麦克风后，AI 能看到摄像头中的视频内容、听到用户说的话，并给予恰当回应。方案需要同时考虑视觉内容理解准确性、语音交互自然度与流畅性，以及长期使用时的成本控制。

文档重点包含两类内容：计划实现哪些用户故事、当前已经实现哪些用户故事；想到哪些控制运营成本的技巧、实际采用了哪些技巧、哪些技巧暂未实现。

### 已实现用户故事小结

当前版本已经覆盖核心对话闭环：摄像头开启、麦克风输入、AI 看图回答、流式文字回复、语音播报、播报打断、成本统计和上下文摘要。视觉侧已经实现细节敏感变化检测和图片质量自适应，能够支持常见看图提问、绘本陪读、物体识别和学习辅导演示。

### 准备实现用户故事小结

下一阶段优先补强状态透明度和细分场景预设。预览帧和发送帧状态说明可以让演示人员解释右下角小图与模型输入的关系；看图讲解、文本识别和操作指导等场景预设可以进一步贴近演示任务。

| C-03 | 画面变化检测 | 静止画面不重复更新发送帧 | 已采用 |

### 已采用技巧说明

| 技巧 | 实现方式 | 对成本的影响 |
|---|---|---|
| 浏览器语音识别 | 使用浏览器能力识别用户语音，不把音频上传到云端 ASR | 降低语音输入 API 成本 |
| 抽帧代替视频流 | 前端只在本地从摄像头画面抽取 JPEG 帧 | 避免持续视频上传和云端视频理解成本 |
| 变化检测 | 通过细节敏感帧差判断画面是否变化 | 减少静态场景下的图片输入 |
| 图片压缩 | 限制最长边像素并用 JPEG 输出 | 减少图片体积和图像 token |
| 自适应质量 | 根据画面复杂度在质量上下限之间计算实际 quality | 简单画面减少体积，复杂画面保留识别质量 |
| 对话摘要 | 历史达到阈值后替换为摘要 | 降低长对话上下文 token |
| token 状态栏 | 展示调用次数、输入/输出 token、总 token、节省 token、估算费用 | 让演示和调参有成本反馈 |
| 场景预设 | 不同场景配置抽帧频率、分辨率、质量和提示词 | 避免所有任务都使用高成本配置 |
| 本地预览缩略图 | 未传输时也能测试抽帧，但不更新对话发送帧 | 方便调试，不增加模型调用成本 |
| 发送即取帧 | 文本发送或语音句子结束时立即抓取最新帧 | 提升视觉准确性，不需要提高常驻上传频率 |
| 成本/质量模式 | 省钱、均衡、高清识别三档联动抽帧频率、分辨率、质量范围和摘要阈值 | 让用户用简单入口选择成本和识别质量 |

### 未实现或暂不采用技巧说明

| 技巧 | 未实现原因 | 后续判断 |
|---|---|---|
| 多帧上下文 | 多帧会明显增加图像 token | 仅在动作理解或高清模式中评估 |
| 模型路由 | 需要多模型接入和任务分类逻辑 | 当前 MVP 先使用统一多模态模型 |
| 相似画面缓存 | 需要缓存命中策略和视觉描述复用策略 | 等真实使用数据后再判断 |
| 埋点采集 | 当前文档只设计事件，不一定接入采集 SDK | 若需要验收数据或成本看板再实现 |

## 端云协同说明

端侧承担可本地完成的任务：摄像头预览、抽帧、变化检测、复杂度分析、图片压缩、语音识别、TTS 回退和 UI 状态展示。云端承担需要大模型能力的任务：多模态理解、对话生成、会话摘要和成本统计。

这种分工可以让应用保持低实现复杂度，又避免把连续视频和音频都上传到云端。对演示和验收场景而言，端侧策略让成本控制可解释，云端模型保证视觉理解和中文回答质量。

## 验证建议

| 验证项 | 方法 |
|---|---|
| 摄像头画面 | 开启摄像头，确认实时预览和右下角缩略图更新 |
| 视觉问答 | 展示物体、绘本或题目，发送问题后检查 AI 回复是否结合画面 |
| 细节变化 | 移动手指、翻页、改变文字区域，观察缩略图和发送帧更新 |
| 语音输入 | 点击语音输入，说一句完整问题，确认自动进入对话 |
| 流式回复 | 发送长问题，确认 AI 回复逐步显示 |
| 语音播报 | 听到 AI 播报后开始输入，确认播报中断 |
| 成本统计 | 多轮对话后查看右上角 token 和估算费用变化 |
| 摘要降本 | 降低摘要阈值并进行长对话，确认摘要触发和 savedTokens 变化 |
