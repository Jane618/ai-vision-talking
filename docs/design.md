# 多模态 AI 对话应用 · 设计文档

> 一款基于国产模型的端云协同多模态对话应用。用户通过浏览器打开摄像头与麦克风，AI 实时看到画面内容、听到用户说的话，并以语音 + 文字形式给予回应。

---

### 1.2 实际实现情况

- **已实现**：US-01 ~ US-10（Web 端完整功能）
- **未实现**：US-11（iOS 版本）
  - 原因：本项目优先级为"Web 优先，有余力再加 iOS"。Web 端涵盖了核心功能，iOS 版本涉及 App Store 审核流程和证书管理，超出当前 MVP 范围。如需实现，建议基于当前 Web 端用 Capacitor/WebView 壳快速包装，或用 SwiftUI + WebRTC 原生实现，整体架构与本文档相同。

### 2.2 关键数据流

1. **用户点击"开始对话"** → 浏览器请求摄像头和麦克风权限
2. **视频流** → Canvas 每隔 N 秒捕获一帧 → 压缩为 JPEG（512×512）→ base64 编码
3. **音频流** → FunASR-WASM 在浏览器本地识别为中文文本 → 实时显示
4. **用户停顿结束** → 后端 POST 请求 `{ image_base64, user_text, session_id }`
5. **后端处理** → 调用豆包多模态 API（图像 + 文本 + 对话历史）→ 获取 AI 文本回复
6. **AI 文本** → 调用火山引擎 TTS API → 生成 MP3/PCM 音频
7. **返回** → HTTP 响应包含 `{ ai_text, audio_data, cost_estimate }`
8. **浏览器** → 播放音频 + 显示文字 + 追加到对话历史

### 2.3 技术选型

| 层 | 技术 | 说明 |
|----|------|------|
| 前端 | Vite + React + TypeScript | 轻量快速，热更新友好 |
| 前端视频 | `navigator.mediaDevices.getUserMedia` | Web 标准 API |
| 前端语音识别 | FunASR-WASM（阿里达摩院开源） | 浏览器本地，零成本，国产 |
| 后端 | Node.js + Express + TypeScript | 简洁，JS/TS 全栈统一 |
| 视觉理解 | 豆包多模态 API（火山引擎 ark/v1 接口） | 国产，图像+文本多模态 |
| 对话推理 | 豆包大模型（同 API，多模态统一调用） | 国产，中文理解优秀 |
| 语音合成 | 火山引擎 TTS API | 国产，中文自然度高 |
| 会话管理 | 内存 Map（MVP）/ Redis（生产） | MVP 简洁优先 |

## 3. 成本控制策略

### 3.1 所有想到的降本技巧

| 编号 | 技巧 | 预估节省 | 说明 |
|------|------|---------|------|
| C-01 | **浏览器本地语音识别**（FunASR-WASM）替代云端 ASR | ~80% 语音成本 | 不调用云端 ASR API |
| C-02 | **智能抽帧**：基于帧差检测，画面无变化不发送 | ~50-70% 视觉成本 | 跳过静态画面 |
| C-03 | **图像压缩**：默认 512×512，JPEG quality=0.7 | ~60% 视觉成本 | 减少 base64 体积 |
| C-04 | **对话历史压缩**：超过 N 轮后自动摘要 | ~30-50% 对话 token | 减少上下文长度 |
| C-05 | **按需调用**：只有用户说话结束后才触发 API | ~50% 总体成本 | 不主动轮询 |
| C-06 | **流式 TTS**：AI 文本分段生成，边生成边返回 | ~20% 等待时间 | 降低首字延迟 |
| C-07 | **本地缓存**：相同/相似画面描述缓存 | ~10-30% 视觉成本 | 场景变化慢时生效 |
| C-08 | **用户可配置**：分辨率/抽帧频率滑块 | 用户可控 | 让用户自己选择性价比 |
| C-09 | **最大 token 限制**：每次 API 调用设置 max_tokens 上限 | ~10% 对话成本 | 避免冗长回复 |
| C-10 | **会话自动超时**：5 分钟无活动自动清理会话 | ~5% | 防止僵尸会话 |
| C-11 | **模型降级**：简单问题用小模型，复杂问题换大模型 | ~30-50% 对话成本 | 需要路由逻辑 |
| C-12 | **批量 TTS**：短句合并成一次 TTS 请求 | ~20% TTS 成本 | 减少 API 调用次数 |
| C-13 | **提示词优化**：简短高效的 system prompt | ~5% | 减少每次输入 token |

### 3.2 实际采用的技巧

| 编号 | 技巧 | 实现位置 | 说明 |
|------|------|---------|------|
| ✅ C-01 | 浏览器本地语音识别 | `frontend/src/asr/` | FunASR-WASM（国产开源），零 API 调用 |
| ✅ C-02 | 智能抽帧（帧差检测） | `frontend/src/video/frameSampler.ts` | 相邻帧像素差阈值判断 |
| ✅ C-03 | 图像压缩 | `frontend/src/video/frameSampler.ts` | 512×512, JPEG quality 可调 |
| ✅ C-04 | 对话历史压缩（简单版） | `backend/src/services/conversation.ts` | 超过 8 轮后仅保留最近 + 系统摘要 |
| ✅ C-05 | 按需调用 | `frontend/src/hooks/useConversation.ts` | 用户停顿 > 1.2s 才触发 |
| ✅ C-08 | 用户可配置 | `frontend/src/components/SettingsPanel.tsx` | 抽帧频率、分辨率、画质滑块 |
| ✅ C-09 | max_tokens 限制 | `backend/src/services/doubao.ts` | 默认 500 tokens |
| ✅ C-10 | 会话自动超时 | `backend/src/services/conversation.ts` | 10 分钟无活动自动清理 |
| ✅ C-13 | 优化的 system prompt | `backend/src/services/conversation.ts` | 简洁中文角色设定 |

### 3.3 未采用的技巧（原因）

| 编号 | 技巧 | 未采用原因 |
|------|------|-----------|
| ❌ C-06 | 流式 TTS | 火山引擎 TTS 流式 API 复杂度较高，MVP 阶段收益有限 |
| ❌ C-07 | 本地缓存 | MVP 会话级别的简单实现已够用，缓存命中率评估需更多用户数据 |
| ❌ C-11 | 模型降级路由 | 需要额外的"问题难度评估"模块，MVP 阶段优先功能完整性 |
| ❌ C-12 | 批量 TTS | 当前单次回复即一个 TTS 请求，批量场景不常见 |

### 3.4 成本估算（基于实现配置）

| 场景 | 每小时调用次数 | 图像 token 估算 | 对话 token 估算 | TTS 字符数 | 估算费用 / 小时 |
|------|--------------|---------------|---------------|----------|-----------------|
| 低活跃（偶尔说话） | 10-15 次 | ~150-300K | ~20-50K | ~3-5K 字 | ¥0.3 - ¥0.8 |
| 中等活跃（正常对话） | 30-50 次 | ~450-900K | ~80-150K | ~10-20K 字 | ¥1.0 - ¥2.5 |
| 高活跃（连续提问） | 60-100 次 | ~900-1800K | ~200-400K | ~30-50K 字 | ¥2.5 - ¥5.0 |

> 估算基于：豆包多模态图像输入约 ¥0.003/次，对话约 ¥0.01/1K tokens，TTS 约 ¥0.02/万字。实际以火山引擎官方定价为准。

## 4. API 设计

### 4.1 核心接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/multimodal` | 多模态对话（图像 + 文本 + 历史） |
| GET | `/api/health` | 健康检查 |
| GET | `/api/config` | 获取前端可配置项（当前帧率/分辨率等） |

### 4.2 POST /api/multimodal

**请求体：**

```json
{
  "sessionId": "uuid-string",
  "image": "base64-encoded-jpeg (可选)",
  "userText": "用户说的话（经过 ASR 识别后）",
  "settings": {
    "frameIntervalMs": 3000,
    "imageQuality": 0.7,
    "imageSize": 512
  }
}
```

**响应体：**

```json
{
  "aiText": "AI 的文本回复",
  "audioData": "base64-encoded-mp3",
  "cost": {
    "imageTokens": 1200,
    "textTokens": 450,
    "totalCalls": 15,
    "estimatedCost": 0.023
  }
}
```

## 5. 部署与运行

### 5.1 环境变量

| 变量 | 说明 |
|------|------|
| `ARK_API_KEY` | 火山引擎方舟 API Key（豆包多模态 + 对话）|
| `ARK_MODEL_ENDPOINT` | 豆包多模态模型 Endpoint ID |
| `VOLC_TTS_APP_ID` | 火山引擎 TTS App ID（可选，不填则用浏览器 TTS 回退）|
| `VOLC_TTS_ACCESS_TOKEN` | 火山引擎 TTS Access Token（可选）|
| `SERVER_PORT` | 后端端口，默认 3001 |

### 5.2 启动方式

```bash
# 1. 安装依赖
cd backend && npm install
cd ../frontend && npm install

# 2. 配置环境变量（见 .env.example）

# 3. 启动后端
cd backend && npm run dev

# 4. 启动前端（另一个终端）
cd frontend && npm run dev

# 5. 浏览器打开 http://localhost:5173
```

### 5.3 生产部署建议

- 前端：Vercel / Netlify 静态部署，或任意 CDN
- 后端：Docker + 任意 Node.js 主机（需 HTTPS，因为 getUserMedia 仅在 HTTPS/localhost 工作）
- 会话管理：内存 Map → Redis（多实例部署必选）

## 6. 安全与隐私

- **API Key 保护**：所有云 API Key 仅在后端环境变量中，前端不可见
- **数据传输**：生产环境必须 HTTPS / WSS
- **本地语音识别**：音频数据不离开浏览器，隐私友好
- **图像数据**：仅在用户说话瞬间的那一帧发送，不持续上传视频流
- **日志**：可选关闭图像内容日志，仅记录调用次数和 token 数
