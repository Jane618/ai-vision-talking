# AI Talking 多模态对话应用技术方案

创建日期：2026-06-13

## 目标与范围

AI Talking 面向“打开摄像头与麦克风后即可和 AI 自然对话”的演示与交付场景。应用需要让 AI 看到摄像头画面、理解用户语音或文本问题，并以流式文字和语音播报回应用户，同时控制多模态模型、TTS 和上下文 token 成本。

当前方案以 Web 应用为主，兼顾移动端壳应用能力。核心路径包含摄像头预览、本地抽帧、语音识别、流式多模态对话、语音播报、对话摘要、token 统计和画面压缩策略。

## 总体架构

```mermaid
flowchart LR
  Camera[摄像头视频流] --> Sampler[前端抽帧与压缩]
  Mic[麦克风输入] --> ASR[浏览器语音识别]
  TextInput[文本输入] --> UI[React 对话界面]
  Sampler --> UI
  ASR --> UI
  UI --> StreamAPI[/api/multimodal/stream]
  StreamAPI --> Conversation[会话与摘要管理]
  Conversation --> Model[豆包多模态模型]
  Model --> StreamAPI
  StreamAPI --> UI
  UI --> TTS[浏览器 TTS 或原生 TTS]
```

前端负责采集、压缩和交互体验；后端负责会话拼装、模型调用、摘要压缩和成本统计。端侧尽可能处理低成本任务，例如摄像头抽帧、画面变化检测、图片压缩、语音识别、TTS 回退和 UI 状态管理；云端只处理需要大模型能力的多模态理解与回答生成。

## 前端方案

前端使用 Vite、React 和 TypeScript。页面分为摄像头模块和对话模块，两者左右平分布局。摄像头模块包含实时预览、画面设置浮层、场景预设、传输控制和右下角抽帧缩略图；对话模块包含消息历史、摘要设置、输入框、语音输入、停止播报和发送按钮。

摄像头开启后会持续进行本地抽帧，用于右下角缩略图测试。只有用户开启“传输画面”并且画面变化检测通过时，才更新对话使用的当前帧。这个设计把“本地预览测试”和“发送给模型的图片”分开，降低误上传和无效 token 消耗。

语音输入基于浏览器语音识别能力。用户点击语音输入后，识别中的临时文本回填到输入框；识别到句子结束后自动发送。AI 播报中，用户开始输入或启动语音输入会中断当前播报，避免 AI 继续说话影响下一轮交互。

## 视觉理解方案

视觉输入采用抽帧而不是上传视频流。每次抽帧从 `<video>` 元素绘制到离屏 canvas，再按用户设置的最长边像素缩放，最终输出 JPEG base64。这样可以用较低实现成本接入多模态模型，也便于控制图片尺寸和压缩质量。

画面变化检测使用细节敏感的帧差算法。当前实现将画面降采样到 `64x64`，综合全局平均灰度差、变化像素比例、Laplacian 边缘变化比例和局部 `8x8` 块最大变化，减少文字、小物体、手势等局部变化被平均值抹平的情况。

图片质量使用复杂度自适应策略。系统会分析当前帧的 Laplacian 方差和边缘像素比例，得到画面复杂度分数；文字密集、纹理丰富的画面接近质量上限，纯色、天空、墙面等低复杂度画面接近质量下限。用户设置保留为上限/下限，既避免过度压缩细节，又减少简单画面的图片体积。

## 语音交互方案

语音交互分为输入和输出两段。输入侧使用浏览器语音识别，减少云端 ASR 调用成本，并把识别结果直接进入对话流程。输出侧优先使用可用的原生或浏览器 TTS；AI 文本以 SSE 流式返回，前端按句子切分并加入播报队列，实现边生成边播。

当前播报队列按标点切分句子，能够降低首句等待时间。后续计划优化过短片段合并策略，避免连续短句造成割裂感，并增加语音识别结束反馈，让用户知道语音内容已经发送或正在等待发送。

## 后端方案

后端使用 Node.js、Express 和 TypeScript。核心接口是 `/api/multimodal/stream`，使用 SSE 返回流式文本片段、摘要事件、完成事件和错误事件。后端接收 `sessionId`、用户文本、可选图像和用户设置，将其组装为 Ark 兼容的多模态消息后调用豆包模型。

会话状态存放在内存结构中，包含历史消息、成本统计、创建时间、最近活跃时间和最近摘要时间。MVP 阶段使用内存便于快速演示；生产部署建议替换为 Redis，以支持多实例扩展和更稳定的会话恢复。

后端还支持托管前端静态产物，并可通过 HTTPS 证书配置提供统一入口。移动端或局域网调试时，只需要访问后端 HTTPS 地址即可加载页面并调用 API。

## 成本控制方案

| 策略 | 当前状态 | 作用 |
|---|---|---|
| 本地语音识别 | 已实现 | 减少云端 ASR 成本 |
| 摄像头抽帧替代视频流 | 已实现 | 避免持续上传视频 |
| 画面变化检测 | 已实现 | 静态画面不更新发送帧 |
| 图片尺寸控制 | 已实现 | 限制最长边像素，降低图像 token |
| JPEG 质量自适应 | 已实现 | 简单画面降低体积，复杂画面保留细节 |
| 对话摘要 | 已实现 | 历史达到阈值后压缩上下文 |
| token 与费用统计 | 已实现 | 在 UI 中展示会话成本 |
| 场景预设 | 已实现 | 不同任务使用不同图像参数和提示词 |
| 发送时抓取最新帧 | 已实现 | 提升视觉准确性，同时不提高常驻上传频率 |
| 成本/质量模式 | 已实现 | 把多个参数组合成省钱、均衡、高清识别等模式 |

## 待补强能力

| 方向 | 计划补强点 | 原因 |
|---|---|---|
| 视觉状态透明 | 区分本地预览帧和对话发送帧 | 避免误解右下角缩略图一定已上传 |
| 语音自然度 | 合并过短 TTS 片段，增加识别结束反馈 | 减少播报割裂感，提高对话确定性 |
| 多帧理解 | 评估最近 2-3 张关键帧上下文 | 用于动作理解，但默认不启用以控制成本 |

## 测试与验证

基础功能验证包括摄像头权限、麦克风权限、右下角抽帧缩略图、画面设置浮层、语音输入、文本输入、流式回复、语音播报、打断播报、摘要开关、token 状态栏和错误提示。视觉准确性验证需要用文字页面、小物体、手势移动和低复杂度背景分别测试抽帧、变化检测和自适应质量。

成本策略验证需要观察 token 状态栏、摘要触发结果、图片质量状态和不同场景预设参数。构建验证使用 `npm run build`，后续若接入自动化测试，可增加前端组件测试和后端接口契约测试。
